# 04 — Оценка качества кодовой базы

## Общая оценка

| Критерий | Оценка | Комментарий |
|----------|--------|-------------|
| Читаемость | ⭐⭐⭐⭐☆ | Код краткий, имена понятные, структура предсказуема. Но комментарии минимальны. |
| Модульность | ⭐⭐⭐☆☆ | Слои разделены, но связи между ними не всегда абстрактны. Сервисы тонкие, без интерфейсов. |
| Связность (Cohesion) | ⭐⭐⭐⭐☆ | Каждый модуль имеет чёткую ответственность. |
| Зацепление (Coupling) | ⭐⭐☆☆☆ | Высокое зацепление: `main.py` напрямую импортирует `current_user` из `api/v1/users.py`; `chat.py` (router) импортирует из `api/v1/users.py`. |
| Тестируемость | ⭐☆☆☆☆ | Тестов нет. Dependency injection присутствует, но нет mock-инфраструктуры. |
| Безопасность | ⭐⭐☆☆☆ | Несколько критических уязвимостей (см. ниже). |
| Надёжность | ⭐⭐☆☆☆ | Нет обработки ошибок, нет graceful shutdown, нет health-check без auth. |

**Общий вердикт:** Проект находится на стадии **раннего прототипа / MVP**. Базовая функциональность работает, но отсутствуют фундаментальные практики production-ready разработки: тесты, обработка ошибок, логирование, безопасность.

## Соответствие стандартам

### SOLID

| Принцип | Статус | Детали |
|---------|--------|--------|
| **S** — Single Responsibility | ⚠️ Частично | `app/main.py` совмещает создание приложения, роутинг HTML-страниц и монтирование роутеров. `app/api/v1/users.py` одновременно конфигурирует FastAPIUsers и экспортирует `current_user` dependency (нарушает инкапсуляцию). |
| **O** — Open/Closed | ❌ Нарушен | Модель LLM (`openai/gpt-4o`) и `base_url` захардкожены в `app/services/chat.py:7,20`. Добавление новой модели требует изменения кода. Системный промпт захардкожен. |
| **L** — Liskov Substitution | ✅ Соблюдён | Наследование `User` от `SQLAlchemyBaseUserTableUUID` + `Base` корректно. |
| **I** — Interface Segregation | ⚠️ Частично | Нет интерфейсов (Python — duck typing), но `UserManager` реализует только нужные методы `BaseUserManager`. |
| **D** — Dependency Inversion | ⚠️ Частично | DI через FastAPI `Depends` есть, но зависимости привязаны к конкретным реализациям (нет абстракций/Protocol). `chat.py` (router) напрямую зависит от `current_user` из `users.py` — не от абстракции. |

### DRY

| Нарушение | Местоположение | Описание |
|-----------|----------------|----------|
| Дублирование `Jinja2Templates` | `app/main.py:19` и `app/core/templates.py:3` | Экземпляр создаётся дважды. `app/core/templates.py` не используется. |
| Дублирование `SECRET` | `app/api/v1/users.py:17` и `app/services/user_manager.py:10` | `SECRET = settings.SECRET` повторяется в двух модулях. |
| Дублирование CSS | `login.html`, `signup.html`, `landing.html` | Идентичные блоки `<style>` (gradient-bg, glass-effect, floating, btn-glow) копируются между шаблонами. Нет базового шаблона (base template). |
| Дублирование `on_after_register` | `app/services/user_manager.py:17` | Хук определён только для логирования, но паттерн не масштабируется. |

### KISS

✅ В целом соблюдён. Код простой и прямолинейный. Возможное исключение — двойная конфигурация auth-backend'ов (JWT + Cookie), из которых для SSR-фронтенда нужен только Cookie.

## Технический долг и запахи кода

### Критические (блокирующие запуск)

| # | Проблема | Местоположение | Влияние |
|---|----------|----------------|---------|
| 1 | **`app/static/` не существует** | `app/main.py:20` | `StaticFiles(directory="app/static")` вызовет `RuntimeError` при запуске. Приложение не стартует. |

### Безопасность

| # | Проблема | Местоположение | Влияние |
|---|----------|----------------|---------|
| 2 | **Дефолтный SECRET** | `app/core/config.py:16` | `SECRET = "your-secret-key-change-this-in-production"` — если не задан через `.env`, JWT подписываются предсказуемым ключом. Полная компрометация auth. |
| 3 | **Prompt injection** | `app/services/chat.py:15-18` | Пользовательский ввод напрямую конкатенируется в промпт без санитизации. Злоумышленник может переопределить системные инструкции. |
| 4 | **Нет валидации `GITHUB_TOKEN`** | `app/core/config.py:13` | Пустая строка — допустимое значение. Приложение запустится, но чат будет падать с 401 от GitHub API. |
| 5 | **Health check требует auth** | `app/main.py:55` | `/health` недоступен для мониторинга без учётных данных. Должен быть публичным. |
| 6 | **Нет CORS** | `app/main.py` | API недоступен для внешних фронтендов; при необходимости — небезопасная конфигурация по умолчанию. |
| 7 | **Нет rate limiting** | — | Нет защиты от brute-force на `/auth/login` и от спама в `/api/chat` (каждый запрос → платный LLM-вызов). |
| 8 | **`echo=settings.DEBUG`** | `app/db/session.py:5` | При `DEBUG=True` весь SQL-вывод (с данными) попадает в stdout — утечка чувствительных данных. |

## Узкие места (Bottlenecks)

| Участок | Описание | Влияние |
|---------|----------|---------|
| **LLM API latency** | Запрос к `https://models.github.ai/inference/` — синхронный await, без streaming. Средняя задержка 2-10 секунд. | Пользователь ждёт полного ответа. При высокой нагрузке — накопление pending запросов. |
| **SQLite concurrency** | SQLite поддерживает один writer одновременно. `aiosqlite` — обёртка над синхронным SQLite в отдельном потоке. | При росте числа пользователей — contention на запись (регистрация, обновление профиля). |
| **Нет connection pool для LLM** | `AsyncOpenAI` клиент — singleton, но нет ограничения на число одновременных запросов. | При всплеске трафика — исчерпание лимитов GitHub Models API (rate limit 429). |
| **CDN Tailwind** | Runtime-компиляция Tailwind в браузере при каждой загрузке страницы. | Замедление First Contentful Paint на 200-500ms. |
| **Отсутствие кэширования шаблонов** | Jinja2Templates без явного кэширования при `--reload`. | Дополнительные I/O операции при каждом запросе HTML-страницы. |
